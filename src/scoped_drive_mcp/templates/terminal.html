More options
Put an MCP server behind Bot RBAC
So that server's tools follow the role. botrbac servers add github -- npx -y @modelcontextprotocol/server-github, or botrbac servers add notes --url https://…/mcp.
Move every server in a config file
When an agent already has several MCP servers. botrbac wrap claude-code (or cursor, gemini, codex) moves them all and keeps a backup; add --dry-run to see the changes first.
Check the agent's own tools
The one-line setup already does this for Claude Code, so shell commands and file edits follow the role (including cmd/gh-style patterns). To turn it off: botrbac hooks remove claude-code --user.
A narrower role for one run
When one session should do less than the computer's role. Add eval "$(botrbac shell-init)" to your shell's startup file, then claude --botrbac --role reviewer.
Check the setup
botrbac doctor lists anything that still goes around Bot RBAC.

Bot RBAC only controls tool calls that go through it. It stops an agent from going around your rules; it cannot stop someone who owns the computer from removing it. Full guide

Control what AI agents on your computers can do. Works with any agent that supports MCP: Claude Code, Codex, Cursor, Gemini CLI and others.

How it works

{% else %}

How it works

{% endif %}

your agent → botrbac on your computer → checks the role → runs the tool, or blocks it

  1. Connect a computer. This puts botrbac between the AI agents on it and their tools: MCP servers, and with Claude Code also its shell and file edits.
  2. Give the computer a role. A role is a list of tools that are allowed; everything else is blocked. Pick it in the Role column of Your terminals and press Change. That is the only place a role gets tied to a computer.
  3. Adjust from Activity. When an agent is blocked, Activity says what it tried, why it was stopped, and how to allow it if it should have been.

Where you want to end up: each computer on a role that fits the work you do there (not Full access), and every agent and tool server going through Bot RBAC. Make a role from a starter, or keep the built-ins:

  • Read-only: agents can look but not change anything. Every new computer starts here.
  • Full access: nothing is blocked; the checks are switched off, but calls are still logged.
  • No tools: blocks everything, to pause a computer.
